# kingsSafe 项目定位

kingsSafe 为 Unity 游戏开发者提供资源和关键运行数据的保护机制，以及可公开复现的攻防验证方法。主要用户是需要保护游戏资产、减少常规修改器影响，同时保持正常玩家体验的开发团队。

## 三个核心功能

| 功能名称 | 价值理念 | 保护对象 |
| --- | --- | --- |
| 资产加固 | 守护创作 | 模型、贴图、音频、动画和关卡等内容资产 |
| 内存保护 | 捍卫公平 | 血量、弹药等关键运行数据及其正常业务状态 |
| 逻辑混淆 | 保护创新 | 核心算法、独有机制、关键业务与安全路径 |

三项为并列核心功能。资产、运行数据和关键实现分别具有独立保护价值，也相互配合。开发先后是工程取舍，不是产品层级。

代码难读程度不是充分指标。逻辑混淆需验证关键函数定位、语义恢复、等价实现与逻辑篡改的成本，并同时检查合法业务和运行代价。

## 公开研究与独立验证

对外定位为面向 Unity 的开源游戏安全加固项目，采用守护创作、捍卫公平、保护创新三项价值表达。官网不使用阵营关系作为品牌叙事。

安全研究提供授权样本中的提取、篡改和还原证据，防护设计据此修复，通过独立验证和同条件复测确认改进。REA 是可接入工具之一，不假定任何官方关联。原失败进入回归集，正常运行与性能结果同样公开。

## 系统交付

| 工作面 | 应交付内容 |
| --- | --- |
| 产品定义 | 用户、资产、威胁范围、目标和限制 |
| 研究设计 | 技术依据、可证伪假设、候选路线和决策记录 |
| 评测体系 | 样本、任务、验证器、对照组、方法和报告格式 |
| 技术实现 | 构建工具、运行时保护与 Unity 适配 |
| 质量保障 | 功能、资源、兼容、性能、故障和恢复测试 |
| 开源协作 | 代码与格式说明、问题报告、复现和贡献约定 |
| 发布维护 | 支持矩阵、版本化产物、迁移、回滚与安全回归 |

定位、目标、路线图、技术方案和评测标准先于实现确定。实现用于验证假设，结果可以促使方案调整或淘汰。

## 开源安全模型

假设攻方知道防护源代码、格式、加载流程和校验方法。实际部署密钥可以不公开，但不能依赖解密器位置或格式保密。客户端独立离线使用资源时，攻方可能从运行环境取得解密能力，这个边界必须接受测试。

拟公开防护实现、格式说明、样本生成器、评测框架和复现方法。实际游戏私钥、真实凭证、未授权资产和个人数据不属于开源交付。示例密钥仅用于互操作，不能依靠其保密程度证明安全。

## 首版价值边界

第一版先完成资源打包、加密与完整性、运行时加载、缓存、卸载、内容等价和攻防评测的完整链条，再开展关键数据保护。内核驱动、DMA 防护、全量反外挂和通用 exe 加壳不进入首版。

# kingsSafe 评测与验证标准

评测在实现前设计，与 G1 到 G7 逐项对应。正常运行正确性、防护效果、性能代价和发布就绪分别判定。一次演示、工具报错或 Agent 自述不能替代验收。

本文是产品实验标准与初始预算提案。2026 年 10 月 30 日的工程机制探针单列于[构建可行性实测](build-hardening-feasibility.md)，不按事后补登记方式计为本文的正式产品验收。

## 实验预注册

每轮在执行前固定并保存：目标编号、威胁层级、可见源码和部署材料、样本摘要、预期输出、验证器版本、工具和模型版本、权限、预算、重复次数、设备、采样方法、通过阈值与异常处理。记录时间和配置摘要，禁止根据已看到的结果回改原标准。

标准变化形成新一轮实验，保留旧结果并说明原因。性能预算在 M0 按设备档位与场景冻结，缺少预算只能报告测量，不能标记发布性能通过。产品验收环境与性能预算尚未冻结；单个 Mac Mono 探针不替代原定 Windows IL2CPP 环境。

## 对照组

| 组 | 配置 | 用途 |
| --- | --- | --- |
| A | 原项目正常发行构建 | 功能、资源、提取和性能基线 |
| B | 接入工具和加载适配，但不加密、不保护数据 | 隔离接入与新路径成本 |
| R | B 加资源容器与运行时解密 | v0.1 核心资源保护 |
| M | R 加关键字段保护 | v0.2 内存保护增量 |
| L | M 加选定逻辑混淆 | 衡量逻辑混淆层收益与代价 |

不能用 Debug 与 Release、Mono 与 IL2CPP、不同资源压缩和画质比较。先确认工具能提取 A/B，攻击任务能修改 A/B 的预设目标；否则该工具或任务不具备有效阳性对照，不能算防护通过。资产公开可获得时，提交仓库原文件不能替代目标包提取证据。

## 资源保护标准

| 编号与目标 | 任务与验证 | 初始通过标准 |
| --- | --- | --- |
| R01 G1 | 固定工具直接打开、改后缀、自动识别、批量导出 | 在有阳性对照的工具与资产组合中，受保护目标直接导出数为 0 |
| R02 G1 | 加解密往返、边界和随机读取 | 每个目标 Bundle 的明文字节与基线完全一致 |
| R03 G2 | 修改密文、头、索引、标签，截断、重排和跨包替换 | 固定负例全部拒绝，未认证明文不进入 Unity |
| R04 G1/G2 | 错密钥、错版本、旧缓存、混合清单、损坏文件 | 错误可定位，无明文回退，无不受控分配或越界 |
| R05 G1 | 加载、使用、卸载、取消和异常后的磁盘检查 | 受控测试目录无完整明文 Bundle、密钥日志或未保护副本 |
| R06 G1 | 同步/异步、依赖、反复加载、随机 Seek 和寿命 | 声明支持组合全部功能通过，无提前释放或泄漏 |
| R07 G1/G5 | 攻方已知源码与格式的定向提取 | 记录是否获得目标资产、耗时、权限、费用和复现 |
| R08 G1/G5 | 可运行客户端的提取或密钥恢复 | 独立验证提取结果，单列运行时边界与批量复用成本 |

R01 通过仅支持“防通用工具直接提取”的声明，不能外推 R07/R08。后两项可出现成功绕过，但必须公开范围和证据；若声称抵抗某一类定向攻击，就需在实验前为该类设定独立安全门槛。

首批直接工具候选为 AssetRipper、UnityPy；AssetStudio 原仓库已归档，只在证明兼容样本时作补充，不用不支持 Unity 版本的解析失败证明安全。[T01/T02/T03](sources.md) M0 固定可运行版本与资源类型矩阵。

提取成功由能解析、显示、播放或重新导入的实际资产验证，不只按输出文件数量。未提取资源数与未识别类型数分别记录。R05 检查是受控目录和生命周期范围的保证，不外推到所有 OS 交换文件、崩溃转储或 GPU 副本。

## 内存防修改标准

| 编号与目标 | 任务 | 初始通过标准 |
| --- | --- | --- |
| M01 G3 | 精确值和变化值搜索，攻击者预知初始数值 | 分别记录搜索定位和最终改值成功率，不仅看地址是否被找到 |
| M02 G3 | 改写选定存储，诱导原逻辑使用目标数值 | 固定非法写入样本在业务使用前检测或拒绝，目标非法收益为 0 |
| M03 G3 | 冻结存储并持续执行消耗与恢复 | 阻断配置非法收益为 0；检测配置单列告警时点，不宣称已阻断 |
| M04 G3 | 恢复旧存储、部分修改、数据与校验一起修改 | 重放、撕裂写与定向修改分别给出结果和适用范围 |
| M05 G3/G5 | 修补检查、替换读取结果、已知源码的定向绕过 | 独立记录成功证据，不把常规修改受阻扩张为全防外挂 |
| M06 G3 | 正常边界、溢出、读写顺序和连续回放 | 与基线业务结果一致，固定样本无误报 |

首批整数样本包括正负数、零、最大最小值、加减、消耗恢复与 checked/unchecked 运算。冻结可能保存一份自洽旧状态，单靠静态校验不能预设必然检出；必须有明确业务进展和期望检查点，不能把“改数值时有告警”替代冻结验收。

业务处置分别记录“检测到”“使用前拒绝”“没有产生非法收益”，日志告警不是阻断证明。报告样本次数和误报数，不把有限样本零误报宣称为任意游戏零误报。未支持的反射、跨线程、序列化、ref/out 等路径应被保留或配置阻断。

## 内存窥探与零改动验收

O01 到 O09 与 Z01 到 Z04 的具体任务见[内存窥探检测专项调研](memory-observation-research.md)。基线只添加插件，不允许以修改字段类型、增加业务标注、替换加载 API、场景挂载或手改构建脚本满足产品接入条件。内部机制对照单列。

内存读取任务必须保留读取方的有效数据与开始、完成时间，目标侧保留事件、决策与退出时间。首次有效读取已完成后的退出，只能说明响应成功，不能算信息读取被阻止。全进程暂停、重复读取、合法访问、不同权限与监测器被修补分别测试。

正常运行下任一确定误终止、保护造成的存档损坏或外部契约变化阻断该配置发布。零误伤的有限样本必须附会话数、设备与小时数。原型未执行为 not-run，不能仅因有反调试 API 或游戏退出就判安全通过。

## 逻辑混淆与持续验证

| 编号与目标 | 任务 | 判定 |
| --- | --- | --- |
| L01 G4 | 相同源码可见性、预算下比较关键函数定位、语义恢复和等价重建 | 实验前固定期望改善幅度，报告绕过成本和不确定性；无改善不计有效保护 |
| L02 G4 | 修补关键业务分支、替换算法结果或移除安全校验 | 记录实际收益，不能只检查某个保护函数仍存在 |
| C01 G5 | 重放已复现的提取或篡改步骤 | 修复前能复现，修复后按同一目标复测，并运行正常路径 |
| C02 G5 | 从干净环境按发布配置生成并验证样本 | 第三方能关联版本、输入、结果与复现步骤，秘密通过受控注入或轮换 |

检测模式与阻断模式分别测试。仅告警的配置必须标明检测能力；声称防止作弊收益的配置必须证明业务使用前拒绝、收益为零。逻辑混淆独立报告保护结果，不能降低其他核心目标、正常功能与性能验收要求。

## 功能和资源无损

所有声明支持的必选用例通过率为 100%，任一确定损坏阻断该配置发布。首批覆盖启动、菜单、场景切换、输入、暂停、离线、退出、资源依赖与释放、Unity 事件、历史存档、协议、诊断与回滚。

资源以未保护 Bundle 为内容基线，保护与解密不能改变其字节，也不重新有损压缩资产。正常加载后检查模型、贴图、音频、动画、Prefab 引用、关卡和材质。对于渲染与物理的跨运行波动，容差由基线重复性预先确定；不能看到结果后放宽。

存档执行 A 写保护版读、保护版写 A 读，并覆盖固定历史文件。网络仅规范化时间戳等已声明的动态字段。检查正常玩家无新增启动器、权限、强制联网和额外操作。

故障实验包括错误密钥、磁盘不足、异常大小、丢失依赖、取消、异常退出、构建中断与旧版本恢复。失败应可定位、不泄漏部署秘密、不回退明文、不破坏原存档。

## 性能测量与预算

至少使用最低目标配置和主流配置两档真实 Windows 设备，M0 固定型号、系统、驱动、Editor、密码库、存储和画质。各组交错执行，记录温度、电源、后台负载与帧率限制。相同工具测量 A/B/R/M/L，运行组件的真实成本保留在结果中。

初始采样为各组至少 20 次独立启动，冷暖启动分别记录；固定回放预热后至少 10 轮，每轮 5 分钟。加载样本包含小资源、大 Bundle、多依赖和随机读取。样本量按基线方差在执行前调整。报告中位数、P95/P99、绝对差值、相对差值和置信区间，不用“无显著差异”直接宣称等价。

以下是设计阶段的研发预算提案，尚不是用户体验承诺或已测结果。M0 在实验前按场景形成固定 profile；若不适用，应在执行前记录替代预算及原因。

| 指标 | 初始预算提案 | 记录要求 |
| --- | --- | --- |
| 冷/暖启动 | 中位耗时增幅不超过 10%，且绝对增量不超过 100 ms | R 对 A，B 辅助归因 |
| 资源加载 | 中位耗时增幅不超过 10%，且绝对增量不超过 100 ms | 每种大小和依赖场景分别判断 |
| 稳态帧时 | P95/P99 绝对增量不超过 0.2 ms，且相对增幅不超过 2% | 不能只比较平均 FPS |
| 解密缓存 | 全局缓存上限 16 MiB | 记录峰值、命中率与实际驻留 |
| 增量内存 | 相同资源驻留状态下峰值增量不超过 32 MiB | 区分缓存、额外副本和密码库 |
| 稳态 GC | 保护组件不引入每帧持续分配 | 加载期分配单列 |
| 数据读写 | 微基准每次成本与整段业务回放均报告 | v0.2 冻结专项预算，不以微基准代替玩家体验 |
| 包体与构建 | 披露字节、增幅和清洁/增量时间 | 不与运行开销混合 |

未冻结预算、未测完设备或无法分辨噪声时，性能为 inconclusive 或 not-run，不能标记通过。超预算先定位到资源、数据或逻辑混淆层，优化或暂停该配置发布；不能静默关闭保护后使用该性能结果。

## 传统与 REA 攻方实验

每个任务至少三种方法：传统工具与脚本、有经验人员配合 AI、REA 类 Agent。已知源码实验向攻方提供 kingsSafe 公开实现与格式，部署秘密和隐藏验证答案分离。攻方获取哪些材料、是否允许管理员权限、网络和运行时观察必须预先记录。

探索轮初始每任务 60 分钟、模型调用费用人民币 100 元等值上限，每种任务与工具配置至少 5 次独立尝试；这些是实验预算，不是保护时长承诺。至少两种模型配置分别报告。重试、人工介入与工具调试计入总成本。

目标资源来自发行样本提取而不是复制答案；关键数据要求真实 Player 出现可验证结果。验证器独立运行，检查来源关联、有效内容和最终业务状态。不同部署版本用于测量单次突破可复用的资产数量、版本范围和后续成本。

## 结果状态与发布

每项结果使用 pass、fail、inconclusive、not-run；未支持样本标记 out-of-scope 并披露覆盖数，不计入通过分母。模型拒绝、工具故障与环境错误单列，不计作防护成功。

报告预算内成功次数、总尝试数、首次有效成功时间、权限、人工时间、费用、提取覆盖和误报。超时属于受预算截断的数据，不记为无限破解时间，也不从统计中直接删除。

v0.1 发布要求 G1/G2、正常功能与资源验收通过，预注册性能 profile 满足，A2/A3 结果与边界公开，签名、迁移和恢复准备齐备。v0.2 另要求 M02/M03/M06 等声明能力通过；未通过则停留研究版本，不得用资源层成绩替代数据保护。

所有报告附环境、代码与格式版本、输入和输出摘要、保护覆盖、原始记录位置、复现步骤和已知绕过。修复后在相同标准下重跑原失败与正常用例，才能标记回归通过。

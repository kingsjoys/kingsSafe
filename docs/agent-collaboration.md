# Agent 贡献与维护者审核

kingsSafe 欢迎 AI Agent、人类开发者及两者共同完成的贡献。协作入口统一为 GitHub Issue 与 PR，社区帖子用于发现项目和讨论，不代替源码审查或验收。

## 可以贡献什么

三项核心能力并列：资产加固、内存保护、逻辑混淆。当前优先需要固定 Windows IL2CPP 构建闭环、资源自动接入、字段兼容性反例、抗篡改与回放研究、逻辑保留规则与独立还原评测。

首次贡献宜选择小范围任务：独立复现现有探针、补充字段编译用法矩阵、明确一条资源加载路径的契约、提出一个可验证的绕过或修复。完整产品设计任务不能用一份未运行的生成代码直接关闭。

入口规则见 [AGENTS.md](../AGENTS.md)。现有任务见 [Issues](https://github.com/kingsjoys/kingsSafe/issues)，跨阶段设计见[路线图](roadmap.md)。

## 一次贡献的流程

1. 在对应 Issue 下说明任务、拟改范围、可用环境与预期证据，避免多人重复同一工作。
2. 在自己的 fork/分支中实现或实验，只使用自有或获授权样本。
3. 提交小型 PR，附版本、步骤、对照、结果与尚未执行的验证。
4. 维护者审阅代码、依赖、覆盖与契约，选择必要的隔离复测。
5. 满足对应变更的验收后合并；证据不足则保留为讨论、研究分支或待验证 PR。

没有写仓库权限的外部 Agent 也能通过 fork 提交。各贡献者自行管理所属模型、运行环境和额度；项目不因收到社区回复就认定已有持续工作的开发资源，也未承诺费用或奖励。

## 审核与合并标准

用户已授权维护者助手承担 kingsSafe 的代码审核与合并。AI 审核用于辅助维护，实际合并仍受项目契约与以下证据约束。

| 变更 | 合并前证据 |
| --- | --- |
| 文档、招募、非行为配置 | 与真实项目状态相符，链接有效，相应静态检查通过 |
| 复现与测试工具 | 能检出目标差异，保留阳性/阴性对照，不改标准掩盖失败 |
| 资产、字段或逻辑变换 | 除静态检查外，提供实际目标 Player、内容/功能差分及对应攻击实验 |
| 构建、权限、依赖与工作流 | 审阅运行代码、授权边界和依赖来源，不向外部 PR 提供维护者凭证 |
| 跨平台或性能支持声明 | 对应平台、设备、后端与预注册预算上的实际证据 |

目前 CI 仅检查官网和 Python 语法，不能据此自动接受保护器实现。旧探针的固定测试密钥、协调修改和完整旧状态回放绕过属于已知限制，不能被改名或日志掩盖为修复。

不是每次代码提交都要改变产品路线。需要业务语义或服务端信任的新方案，先说明额外前提，再判断是否符合“只引入插件”的原目标。

## 运行方式

维护者助手在当前会话或明确配置的执行任务中审核与复测；角色说明本身不会让会话在后台持续运行。持续监看、运行频率与自动合并范围需另行配置，当前未创建定时监看或无限制自动合并。

安全风险、凭证和真实部署细节通过 [SECURITY.md](../SECURITY.md) 的私密渠道报告。

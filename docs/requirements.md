# kingsSafe 目标与要求

三个并列核心功能为资产加固、内存保护、逻辑混淆，对应守护创作、捍卫公平、保护创新。先交付资产加固，再开展关键数据内存保护，逻辑混淆保留独立目标与评测。设计和评测先行，实现服从透明运行、功能与资源无损和性能开销单独实测的约束。

## 保护目标

| 编号 | 目标 | 首批覆盖 | 成功标准 |
| --- | --- | --- | --- |
| G1 | 防资源直接拆包 | 清单内本地 AssetBundle | 常见工具无法直接获得受保护资产，配套加载后内容等价 |
| G2 | 防资源篡改与混包 | 容器、块、索引和版本绑定 | 错误或替换内容在交给 Unity 使用前被拒绝 |
| G3 | 关键数据防修改 | 指定主线程普通托管整数字段 | 阻断配置的预注册改值与冻结任务不能产生目标非法收益，检测另列 |
| G4 | 逻辑混淆 | 核心算法、独有机制、业务及安全路径 | 相同任务下提高定位、还原或篡改成本，兼容性保持 |
| G5 | 持续验证 | 传统工具、人工和 REA 类 Agent | 有可复现记录，修复后原绕过进入回归集 |
| G6 | 内存窥探探测与响应 | 首批 Windows 调试与特定独立内存区域的候选机制 | 按事件分别证明检测、首次读取结果、响应时序与误终止，不外推所有外部读取 |
| G7 | 零业务改动接入 | 版本声明兼容的工程 | 只引入插件，原入口构建，源码、资源、场景和既有构建脚本不需手改 |

G1/G2 是 v0.1 的主要交付，G3 是 v0.2 的主要交付。G4 为独立核心目标，按技术可行性与路线图推进；不能仅以方法改名或反编译文本变复杂证明有效。G1 通过不等同于抵抗已知源码后的定向解密或运行时提取。

## 威胁范围

| 层级 | 攻方条件 | 应报告结果 |
| --- | --- | --- |
| A1 | 通用工具，直接识别和批量导出发行资源 | 首版重点阻止的直接提取 |
| A2 | 已知格式和源码，可编写定向处理程序 | 定向提取成功率、时间与成本 |
| A3 | 可运行客户端并观察加载、解密和内存 | 运行时提取、密钥恢复和绕过证据 |
| M1 | 用户态常规修改器，搜索、改值、冻结 | 是否产生实际作弊效果、是否检测 |
| M2 | 已知源码的定向修改、注入或保护代码补丁 | 深层绕过能力与限制 |
| M3 | 内核、恶意驱动、DMA 或外部视觉设备 | 不属于首轮防护承诺，结果单列 |

黑盒与已知源码条件都需报告，仅在自有或明确授权对象上评测。

## 透明与无损契约

玩家通过原入口运行，无新增启动器、管理员权限、安全弹窗或强制联网。资源解密、受保护值读写和完整性组件可以在客户端内运行。不默认阻止正常录屏、覆盖层或虚拟机，也不以工具进程名作为唯一作弊证据。

| 维度 | 要求 | 验证方式 |
| --- | --- | --- |
| 功能 | 相同合法输入产生相同业务语义与错误处理 | Player 回放和状态差分 |
| 资源 | 不重新有损压缩，不降低分辨率、精度和音质 | 解密后 Bundle 字节与基线相同，加载内容对照 |
| 存档 | 原格式与历史数据兼容 | 基线和保护版本双向读写 |
| 协议 | 外部消息和服务端契约不变 | 规范化消息对照 |
| 接入 | 只引入插件，默认配置与适配由插件生成，原 Build 入口不变 | 记录包引入外的人工步骤，任一必须手改业务的步骤均不满足该目标 |
| 运维 | 可诊断、迁移与回滚 | 故障演练与诊断验证 |
| 性能 | 加解密、数据校验和加载开销单独测量 | 对照组、设备矩阵和预注册预算 |

功能和资源无损是硬要求。性能不再按绝对零开销定义，预算在实验前固定；未定义预算可以测量，但不能宣称满足发布性能要求。不能看到结果后临时放宽预算。

产品目标同时要求玩家运行透明与团队零业务改动接入。AssetBundle、Addressables 等所需加载适配应由插件自动完成，不能要求团队替换原加载调用、改字段类型、标注业务字段、挂载场景组件或重写构建脚本。未覆盖的 Resources、内置场景、反射或第三方路径列为未支持；无法满足默认必要覆盖时构建失败。只加插件不等于任意工程全部对象均已覆盖。

只处理本次构建的工作副本与产物，允许引入插件产生的包注册和锁文件变化。手工加载门面、显式保护类型可以用作内部机制对照，不能计为零改动产品通过。

## 首版范围

首个目标为 Unity 6.3 LTS 一个固定补丁、Windows x64、IL2CPP。M0 固定 Editor、构建模块、原生工具链、加密库和测试设备，候选 API 不等于已验证支持。

v0.1 先支持本地 AssetBundle 容器和加载，再按固定 Addressables 版本研究 provider 适配。同步、异步、依赖与卸载以实际通过矩阵为准。远程下载、CDN、更新和补丁预留设计，未验收前不列为支持。

v0.2 先支持自有普通托管类中、主线程访问的少量非序列化整数数据。反射、ref/out、跨线程、显式内存布局、native interop、Burst、Jobs 和热更新字段先排除。必选目标无法安全处理时阻断配置，不得静默跳过并报告成功。

## 内存窥探研究目标

将“检测到调试、窥探或篡改后终止自身应用”列为 G6 研究路线，保持无新增驱动、常驻服务与管理员权限的默认约束。探测到的事件、读取是否成功、处置时点与业务收益分别验收。守卫页、诱饵和调试状态均不预先等同于全量读取通知。

正常开发诊断与玩家运行不能被误终止；强制退出时的数据安全必须验证。Windows、Android、iOS 单独建立适配与结果，不能跨平台外推。详见[内存窥探检测专项调研](memory-observation-research.md)。

## 接入与失败处理

工具只修改本次输出与中间副本，业务源码、原始资产、Unity 安装和共享缓存保持原样。发行资源可以变为加密容器，原始资产内部保留。签名内容变化后须重新签名。

资源验证或解密失败时拒绝加载并提供可定位错误，不自动退回明文副本。关键数据篡改在读取或使用前报告；不静默改成零、不自动封号、不覆盖原存档。业务处置接口和默认行为须先设计并验证。

实际密钥、内容版本、缓存与更新必须对应。签名私钥不进客户端；解密材料交付、轮换与可提取边界明确记录。离线配置不新增强制联网依赖。

## 状态与评测

每个目标对应[评测与验证标准](validation.md)中的任务、对照与判定。功能正确、安全效果、性能和发布就绪分别报告。未执行为 not-run，证据不足为 inconclusive。

当前阶段只建立文档与实验设计。源代码、运行组件、开源发布和任何保护指标不能标记为已完成。

# kingsSafe 系统路线图

路线图以可核验产物和阶段条件推进。防护代码、攻方适配、样本、评测、质量保障与开源维护共同组成交付，不按代码量或单次演示决定完成。

## 阶段与进入条件

| 阶段 | 产物 | 进入下一阶段条件 |
| --- | --- | --- |
| S0 定位与评测设计 | 定位、目标、威胁模型、候选架构、标准与风险清单 | G1 到 G7 有对应实验，透明与无损定义一致，决策可追踪 |
| S1 资源可行性 | 锁定环境和样本，验证容器、密码库与 Stream 接入 | 实际 IL2CPP Player 可加载，往返字节相同 |
| S2 资源版本 | v0.1 工具、加载组件、缓存与故障处理、攻防和性能报告 | G1/G2 与兼容验收通过，预算满足，已知源码结果披露 |
| S3 关键数据版本 | v0.2 受限字段保护、透明接入与修改器实验 | 搜索、修改、冻结分别验证，探测与终止独立验收，零业务改动与正常读写契约保持 |
| S4 逻辑混淆 | 核心算法、独有机制与关键路径的变换及独立实验 | 定位、还原或篡改成本改善，业务等价，开销已测 |
| S5 持续协作与扩展 | 复现、修复回归、兼容矩阵、迁移与发布 | 各次发布重新满足对应阶段标准 |

问题处理和实验记录从 S0 开始。逻辑混淆可并行开展早期研究；三项产品能力并列，工程上仍先交付资产加固、再关键数据内存保护。

## 设计先行

S0 形成[定位](positioning.md)、[目标](requirements.md)、[技术方案](architecture.md)、[第一版计划](mvp-plan.md)、[评测标准](validation.md)和[协作约定](open-collaboration.md)。这些设计文档先于机制实现建立。

技术决策记录包含问题、候选、依据、选择、替代方案、风险、验证任务和回退方式。首批决策为资源范围、容器加密配置、离线密钥交付、加载入口、缓存形式、字段接入与篡改处置。重要路线变化同步更新目标和评测。

## 构建加固可行性研究

2026 年 10 月 30 日完成 B0：Mac Mono 隔离小样本保留原业务源码与构建入口，只引入研究插件后，自动带入资源加载桥接、字段访问改写与私有方法改名；正常结果保持，协调修改与完整旧状态回放可绕过。详见[实测与 B1—B6 决策门槛](build-hardening-feasibility.md)。这只完成机制探针，没有满足 S1 的实际 Windows IL2CPP Player 条件，也没有产品性能与防护强度验收。

下一步先补原定 Windows x64 IL2CPP 闭环，再扩大资源零改动适配、字段兼容与抗绕过、逻辑与 REA 评测。资源首版优先级与三项核心地位保持。

## 内存窥探专项研究

将被观察后探测与自终止列入内存保护研究，并以零业务改动为接入门槛。先执行专项 P0 到 P2：原工程只加插件、独立双进程读取、实际 Unity IL2CPP 嵌入；再验证数据变换、误终止、响应时序与移动平台。完整任务见[专项调研](memory-observation-research.md)。已完成的字段机制探针不等于窥探检测；外部读取和自终止实验仍为 not-run。

## 核心假设与风险

| 假设或风险 | 验证 | 不成立时处理 |
| --- | --- | --- |
| 容器能阻止直接提取 | A1 工具集与原包阳性对照 | 修正保护链，不以改后缀替代 |
| 流式加载控制驻留和峰值 | 随机读取、生命周期和内存实测 | 调整分块与缓冲，披露明文边界 |
| 开源实现下仍提高攻击成本 | A2/A3 已知源码任务 | 披露绕过，改进或收窄承诺 |
| 数据表示和校验抵抗修改 | M1 搜索、写入与冻结 | 调整保护和检查时机 |
| 插桩能降低业务改动 | 受限字段和危险用法矩阵 | 收窄范围或采用明确适配 |
| 功能不变且开销可接受 | Player 差分和预注册预算 | 修复、优化或暂缓配置发布 |

## 发布维护

v0.1 与 v0.2 分别交付支持版本、保护对象、未支持路径、已知绕过、性能表、复现步骤和迁移说明。实现完成、研究完成和可发布是不同状态；阴性结果可以完成研究，不能让无效保护通过产品验收。

项目采用 Apache-2.0，第三方依赖与样本资产分发权独立核对。当前源码与研究公开不代表产品版本发布。每版固定代码、格式、样本、验证器与报告版本。

排期取决于环境、样本、实验范围和维护投入。Unity 授权、固定补丁和 Windows 设备在 S1 核实，当前不预填开发天数或未测指标。

# kingsSafe 攻防演练

攻防演练直接检验加固后的游戏能应对哪些破解挑战。验证对象是加固产物，围绕资产提取、内存修改和逻辑还原三个方向展开。

## kingsSafe 与 REA

kingsSafe 保护选定的资产、关键数据与业务逻辑。REA 类工具作为逆向分析手段之一，与传统工具共同用于适合的实验任务。不同工具是否支持某项任务应先验证，不能用单一工具替代所有测试。

官网的 VS 表达防护与分析挑战之间的对照关系。工程团队按版本提供验证范围和结果，接入方据此评估适用性。

## 资产提取挑战

对照未加固与加固后的同一组资源，检查直接拆包和批量提取的成功率、资源完整性与可用性。定向分析和运行时提取分别记录，明确工具、耗时与获得的内容。

## 内存修改挑战

对照关键字段的搜索、改值与冻结操作，检查异常能否被检测、操作是否被拒绝，以及是否产生实际作弊收益。正常业务写入保持有效，误报单独记录。

## 逻辑还原挑战

针对固定核心函数或机制，比较传统工具与 AI 辅助分析下的定位、理解、等价还原和行为篡改结果。记录分析条件、投入时间与还原正确性，判断加固带来的成本变化。

## 如何阅读结果

| 结果内容 | 判断依据 |
| --- | --- |
| 防护效果 | 三类任务在同一目标加固前后的差异 |
| 功能与资源 | 业务行为、资源内容、存档与协议的一致性 |
| 运行代价 | 固定设备与场景下的加载、帧时、内存及 GC |
| 可复现性 | 版本、工具、配置、操作记录与原始证据 |

设计目标与实测结论分开呈现。实际结果随经过验证的版本公布，具体判定见[评测方法](validation.md)。

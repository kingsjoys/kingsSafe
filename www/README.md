# kingsSafe 官网

中文官方网站初版，使用原生 HTML、CSS 和 JavaScript，无第三方前端依赖。网站介绍项目定位、资产加固、内存保护与逻辑混淆、工作机制与评测，并提供面向开发者的产品文档中心。

## 本地使用

需要 Node.js。先运行 npm run build，再运行 npm run dev，打开终端输出的本地地址。npm run check 检查静态资源、锚点、脚本语法和文档数量，无须安装依赖。

## 目录

- src：官网页面、样式、交互和品牌 SVG。
- src/content：四篇面向开发者的产品指南，以及三篇公开技术参考。
- scripts：构建、预览和静态检查。
- dist：构建输出，由脚本生成。
- ../.github/workflows/pages.yml：GitHub Pages 自动构建与部署。

产品指南在 src/content 修改；公开技术参考 architecture、validation、sources 从上级 docs 按清单同步。内部路线图与任务计划不进入官网。独立取出网站仓库时保留 src/content，即可离线构建。

## 内容边界

当前产品处于设计与研究阶段，页面不展示虚构客户、测试成绩或已实现能力。工作机制流程为设计示意。下载链接提供产品文档，源码与研究位于 [kingsjoys/kingsSafe](https://github.com/kingsjoys/kingsSafe)，原创内容采用 Apache-2.0。源码公开与产品验收分别管理。

## 验证

页面应检查桌面和手机布局、主导航、移动菜单、验证工作机制流程、FAQ、文档切换、下载和浏览器历史。性能预算提案由文档展示，不作为实测宣传。

## 首页信息结构

首屏直接展示资产加固、内存保护、逻辑混淆及其目标：守护创作、捍卫公平、保护创新。二屏展示“集成无侵入 · 体验零干扰”的设计目标，以代码与资产 → Unity → Build → iOS / Android / Windows 的流水线说明工作机制，kingsSafe 从 Build 上方接入构建环节；各平台对号为设计目标示意。后续依次为攻防演练、接入与使用问答、产品文档入口。文档分为产品介绍、接入与构建、三项核心防护、攻防演练，以及技术参考。攻防演练以 kingsSafe 保护罩与 REA 分析挑战相对展示，罩内为资产、内存和逻辑，中间用 VS 与“经得起真实挑战”连接两侧，详细对照方法在演练文档中说明。研发路线图与第一版任务计划保留在项目内部文档，不随官网构建发布。官网构建仅同步明确列入清单的公开参考文档。

本地执行 npm run build 和 npm run dev，在 http://127.0.0.1:4173/ 预览。主分支相关改动通过 GitHub Actions 自动发布到 [GitHub Pages](https://safe.kingsjoys.com/)，PR 只检查不发布。二级域名绑定见[部署说明](../docs/deployment.md)。

视觉规范：整站不使用装饰性边框或分隔线，通过色块、留白与柔和阴影区分区域；保留键盘焦点提示。

配色使用统一角色变量：中性浅底、白色卡片、冷调浅绿分区、品牌深绿与说明文字色。REA 使用同色系深绿面板；正文和小字按所在底色检查可读性。
